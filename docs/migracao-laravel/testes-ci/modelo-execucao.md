# Registro de execucao de caso

Copiar este modelo para o registro da rodada definido pela equipe. Preencher a partir de uma execucao observada.

## Identificacao

- ID do caso e versao do catalogo
- Data e responsavel pela execucao
- Branch e commit do codigo
- PHP, Laravel e identificacao do lock de cada runtime
- Ambiente e origem dos dados de teste
- Pre-condicoes verificadas

## Procedimento

Registrar os passos e comandos efetivamente usados, com identificadores ficticios e segredos removidos. Informar preparacao de sessao, uso de duble e supervisao de escrita quando aplicaveis.

## Classificacao

Escolher uma classificacao e justificar com evidencias.

- Planejado - caso ainda por executar.
- Bloqueado - alguma pre-condicao impede executar.
- Aprovado - o caso foi exercitado e corresponde ao comportamento esperado da referencia.
- Divergente - diferenca observada entre referencia e destino.
- Inconclusivo - a observacao permite pouca cobertura, como timeout ou falha igual nos dois lados.

Comparacao de sintaxe deve distinguir falhas pre-existentes de falhas novas, conforme a proposta do pipeline.

## Encaminhamento

Descrever limitacoes, area responsavel pela analise e proxima acao. Acrescentar link do issue/PR quando existir. Revisar dados de evidencias antes de publicar, removendo credenciais, sessoes, tokens e dados pessoais.
